# Marketing layer boundaries

- **One design system.** Every public page (the home, the institutional pages and the campaign pages in `app/[locale]/(funil)/`) composes the primitives in `apps/web/src/components/marketing/`: `Section`/`Container`/`SectionHeader` plus the archetypes listed in `catalog.json`. Never hand-tuned per-page spacing or widths, never a parallel stylesheet vocabulary. The inherited MedChina "Landing DS" was removed on 2026-09-30.
- The `marketing-page` skill is MANDATORY for any create/edit/add-section under `app/[locale]/(marketing)`, `app/[locale]/(funil)` or `components/marketing`. The `PreToolUse` hook (`.claude/hooks/marketing-guard.mjs`) loads it automatically on Write/Edit in all three, and the `PostToolUse` lint (`.claude/hooks/marketing-lint.mjs`) checks every written file there. A file changed by a script bypasses both hooks: load the skill yourself and run the lint on it by hand.
- The committed visual direction lives in `docs/DESIGN.md` and is STRICT: new pages, edits and new sections INHERIT it. Never re-run the direction engine or restyle the UI unless the user explicitly asks for a "redesign". Adding a section triggers a whole-page coherence pass so all sections stay aesthetically aligned.
- **Locales are in the path** (phase 7.1): Portuguese at the root (`/planos`), English under `/en` with translated addresses (`/en/pricing`). Every public page lives under `app/[locale]/` in a folder named after its Portuguese (internal) path, and is declared in `apps/web/src/i18n/routing.ts` (`pathnames`) with both addresses. That declaration is also what makes the middleware treat it as public: there is no separate list of public pages. Only the public site is routed this way; sign-in, the member area, checkout and the admin keep the visitor's cookie/profile language and have no locale in the URL.
- **No MUI on the public site** (the public shell, decided 2026-10-07, `docs/PLANO-IMPLEMENTACAO.md`, "Casca pública"). The root layout mounts no provider; the signed-in areas mount `components/layout/app-shell.tsx` (MUI, its styling engine, every catalog, the snackbars, `style/app.css`) in their own layouts. Nothing a public page reaches imports `@mui/*`, `@emotion/*`, `notistack`, `formik` or `yup`: buttons, fields, checkboxes and notices are the primitives in `components/site/` (styled in `style/site/site.css` with the look MUI had), a disclosure is `<details className="site-disclosure">`, a menu or modal a native `<dialog className="site-drawer">`, a public form validates with plain state and the same rules as its server action. A client component of the public site reads only the `marketing` keys listed in `src/i18n/public-client-messages.ts`, written as literals in its file. `lib/public-shell.test.ts` walks the import graph of the public pages and the marketing lint blocks the import (`[mui-on-public]`). With MUI in the root layout the home scored 55 on a phone.
- Internal links on public surfaces go through `LocaleLink` (`components/marketing/locale-link.tsx`, used by `SiteButton` for an internal `href`) or `localizeHref`: `href` is the internal Portuguese path, the link renders the address of the language being read. Links to `/auth/*` and other non-public routes pass through unchanged and are not prefetched (`leavesPublicSite` in `src/i18n/routing.ts`): they load the other shell.
- An INDEXED page also goes to `apps/web/src/app/sitemap.ts`, which emits it once per language with hreflang alternates. A `noindex` page (the campaign pages in `(funil)`, `/fundadores`, `/verificar/[ref]`) stays out of the sitemap and is named in its exclusion comment. Indexing is decided by `metadata` + `sitemap.ts`, never by the route group.
- `/ajuda` and `/blog` are DB-managed: content is written in `/admin/help` / `/admin/blog` and fetched through `apps/web/src/lib/public-content.ts` (anon client, published rows). An address in a language serves content written in that language, never a fallback; translations are separate rows linked by `translation_group`, each with its own slug. The public catalog (`/catalogo`, `/catalogo/[slug]`, the numbers of the home) reads published modules through `apps/web/src/lib/catalog/public.ts` under the same rule: a module whose name has no English text stays out of the English pages and the English sitemap, and a catalog that could not be read is never shown as an empty one. Markdown renders via `components/marketing/markdown-prose.tsx`. Never interpolate DB content as raw HTML.
- SEO is part of every page, per `docs/SEO.md`: exactly one `<h1>` (the page title: `SectionHeader as="h1"` / `PricingSection headingAs="h1"` when the lead is not a `<Hero>`), a localized title + description via `generateMetadata` that spreads `publicPageMetadata({ path, locale })` from `lib/seo.ts` (canonical, hreflang with `x-default`, Open Graph URL and locale), and structured data through `<JsonLd>` (`components/marketing/json-ld.tsx`), never a hand-written `<script>`. `Organization`/`FAQPage`/`Product` schemas are already emitted by the layout/`Faq`/`PricingSection`; do not duplicate them. Inner pages add `BreadcrumbJsonLd`. A missing page answers a real 404 and a moved one a real redirect: never put a loading boundary (`loading.tsx`, or a `<Suspense>` around the children of a layout) above a public page, because the response would start before `notFound()` or `redirect()` runs and go out as a 200.
- Marketing copy lives in the `marketing` i18n namespace, in BOTH locale files (`pt-BR`, `en`), campaign pages included. No hardcoded strings. The home's structured copy lives in `components/marketing/home-copy/{pt-BR,en}.ts`, with `pt-BR.ts` as the structural source of truth (TypeScript refuses the build when `en.ts` drifts). Emphasis is inline (`**em**`, `__strong__`, `==mark==`, `\n`), rendered by `home-copy/rich.tsx`; never put JSX in a copy file. The home's text follows `docs/HOME-COPY.md`, the copy the product owner delivered (committed as delivered): what it asks and the platform cannot back stays out of the page and goes to the owner as a decision.
- **Blocking on every public page**: exactly one `<h1>`, real `alt` text, no fabricated testimonials, metrics or logos, prices and limits read from data (`plans`), no struck-through price and no "from/to" pair anywhere (a coupon is named beside the price it gives: `priceCondition` on `PricingSection`), a seats counter or deadline only on `/fundadores` and from server state (`founders_offer()`), and no claim that the club spends AI credit on the member's behalf.
- **The free rung is never advertised.** No public page or campaign page offers a free plan or a free account, shows a "grátis"/"free" badge on an app, or lists a free column in pricing: the account with no purchase is reached only through content links (`?origem=…&utm_campaign=…`) and the installer's message, and it installs only the entry version of each app (decision of 2026-10-06, `docs/PRODUCT.md`). The one allowed "free" is the waitlist FAQ saying the list itself costs nothing.
- **Copy rules** (the home brief, decided 2026-10-07, `docs/PRODUCT.md`): no dash (— or –), no exclamation mark and no emoji in any visible text, `alt` and `aria-label` included (© and → stay, on purpose), and none of the banned words: desbloqueie, potencialize, sem esforço, soluções inovadoras; unlock, elevate, empower, seamless, robust, supercharge, game-changing, "it's not just". Where a dash would go, write a colon, a comma or a new sentence; separate items with "·"; a missing value hides its line instead of printing a placeholder. The rule covers the member area, the e-mails, the bell and the CLI's messages too; `lib/i18n/copy-rules.test.ts`, pgTAP `0033_copy_rules` and the e2e text check fail when a mark comes back.
- **Colour on text** (WCAG 2.2 AA, `docs/DESIGN.md`, palette usage): the primary is the yellow of the logo, a FILL. It is never the colour of text, a link, an icon or a focus ring on a light ground (1.5:1). A label on a primary fill is `text-primary-contrast`; the primary as a foreground is `text-primary-ink` (charcoal in light mode, yellow in dark); bare `text-primary` only on the deep band. An eyebrow is `<Eyebrow>`, the accent phrase of a headline is `<em>` under the `site-emphasis` class, a tint of the primary is `/20` or more. The accent hues go on icons, bars and fills while the words keep text colours. The shared components follow it; a page must too (`lib/palette-contrast.test.ts` fails otherwise).
- Motion is CSS first: the hero entrance and `Float` are CSS animations, `Reveal` is a CSS transition started by `watchEntry` (one shared IntersectionObserver in `components/marketing/motion.ts`), `CountUp` is a short frame loop. GSAP is loaded by `Parallax` alone, on demand. Never add a scripted timeline or a ScrollTrigger to a page, and never an animation without an end. Transform + opacity only, honoring `prefers-reduced-motion`. Never import GSAP in admin code.
- Site identity (name, tagline, siteUrl, favicons) comes from `apps/web/src/brand.ts`; the logo is the single component `components/logo/logo.tsx`.
- **Measurement is declared, never a new tracker.** A click worth measuring carries `data-track="<event>"` and `data-track-<prop>` attributes (or `trackAttributes()` from `lib/site-events.ts` on a link built in code), a section worth measuring passes `track="<key>"` to `Section` or the component that wraps one, and the one listener in `MarketingAnalytics` reports them to GA4 and the Pixel. The vocabulary is the one in `docs/TRACKING.md` ("Site events"): add to it there before using a new name. Never add PostHog or any other tracker, never write site events to the database, and never read the segment from anywhere but `lib/site-segment.ts`.
