# flyee.club web (apps/web)

Next.js 15 (App Router) + React 19 — the only app of the flyee.club platform: public site, member dashboard, checkout, admin consoles and (from phase 3) the CLI delivery API. See the root `CLAUDE.md`, `docs/PRODUCT.md` and `docs/PLANO-IMPLEMENTACAO.md`.

> The database is the baseline in `packages/db/migrations` (`0000`–`0018`, described in `packages/db/README.md`). Prefer the function name when searching for a rule.

## Stack and conventions

- **UI**: MUI v9 is the base. Before building a component, look for a MUI or MUI X equivalent (installed: Data Grid + Pro, Charts + Pro, Date Pickers, Tree View, Lab). Icons: **Phosphor** through the `@/icons/nexture/*` tsconfig alias (real adapters plus Nexture fallback stubs, see `src/icons/README.md`); never import an icon library directly.
- **Styling**: MUI theme driven by CSS variables (`hsl(var(--token))`) from `@flyee/design-tokens`. Component overrides live in `src/style/**/*.css` inside CSS layers (`theme, base, mui, components, utilities`). Tailwind 4 for layout utilities, merged with `tailwind-merge`. Run `npm run check:mui-classes` after touching `src/style/**`.
- **Themes**: one locked palette (`theme-green`, provisional) × light/dark, applied as classes on `<html>` by `src/theme/theme-provider.tsx`. Fonts: Mulish (`--font-body`), Urbanist (`--font-heading`); `font-display` falls back to Urbanist.
- **Forms**: Formik + Yup. Semantic data (phone, CPF/CNPJ, CEP, money) uses `components/product/fields/*`, never a raw `TextField`; persist digits, never masks.
- **i18n**: next-intl; every user-facing string goes through messages. Locales `pt-BR` (default) and `en`; catalogs in `packages/content/messages/`. `src/lib/i18n/messages.test.ts` pins key parity, no blank values and identical ICU placeholders. `node scripts/prune-messages.mjs --check` fails on keys no code renders and on keys the code renders that the catalog lacks. Namespaces: `marketing` (public site), `auth`, `product` (member dashboard, billing, settings), `dashboard` (chrome and menu). The home's copy lives in `components/marketing/home-copy/{pt-BR,en}.ts`; `pt-BR.ts` is the structural source of truth (`HomeCopy = typeof homeCopyPtBR`).
- **Admin copy is hardcoded pt-BR**, outside i18n: the operator surface has one reader. Code comments stay in English; a database value (enum, slug, status) is mapped to a label, never shown raw. `components/data-grid/data-table.tsx` takes its grid chrome from MUI X's own locale pack.
- **Which language a request is in** is answered in ONE place, `lib/locale-request.ts` (`resolveRequestLocale`), used by `i18n/request.ts`. The cookie is the visitor's choice and always wins; otherwise `lib/locale-detection.ts` decides from `Accept-Language`, then Vercel's `x-vercel-ip-country`. Three rules are load-bearing: detection happens at RENDER time, not only in the middleware (a cookie set by the middleware lands on the response); a crawler is never switched (`isCrawler`); an automatic switch is always announced (`COOKIE_KEYS.localeAuto`). Phase 7.1 moves the PUBLIC site to path locales (`app/[locale]`, next-intl `pathnames`, English under `/en`); dashboard, admin, auth and checkout keep this cookie and profile flow.
- **Path alias**: `@/*` → `./src/*`. **Brand**: identity comes from `@flyee/content` (`src/brand.ts` re-exports it); the logo is the single component `src/components/logo/logo.tsx`.
- **Remote data**: `lib/remote-state.ts` (`RemoteState<T>`: idle, loading, success, empty, error). An error is never rendered as empty.

## Member dashboard (product layer)

- Routes: `/inicio` (`DEFAULTS.appRoot`; interim home with the activation checklist and an empty state), `/settings` (profile and avatar, credentials), `/settings/security` (2FA, sign-in history), `/settings/connections` (OAuth clients holding a live token, with revoke; becomes `/settings/devices` in phase 5), `/settings/billing`. Phase 5 adds `/modulos`, `/receitas`, `/novidades`, `/encontros`, `/roadmap`, `/settings/devices` and the onboarding wizard; the dashboard catalog is `/modulos` because the public one is `/catalogo`.
- **Activation** (`lib/onboarding.ts`): four steps with LIVE predicates, never click tracking — profile (segment, AI tool, language) → access (kit or plan) → install (`npx flyee login`) → first run (closed by the CLI's first `tool.executed`). The facts come from the definer RPC `member_activation_facts()` (phase 2); until it exists every fact reads false. `isActivated` = a device AND a first execution. `resolvePostAuthDestination` is called by sign-in, sign-up, `/auth/callback` and `/auth/two-factor`; never put that check in the middleware.
- **Entitlements**: `hooks/use-entitlements.ts` calls `org_entitlements(org)`, the single answer to what a workspace may use: the free floor, live grants (the kit, licenses, courtesies), the live subscription with its add-ons, and an unconfirmed PIX inside its window, merged so more sources never mean fewer rights, with the tier and the sources named. Screens branch on it, never on plan names. `org_has_entitlement(org, key)` is the yes/no form for policies and gates. `components/product/gate-notice.tsx` renders the gate states (`available`, `loading`, `unknown` with retry, `blocked` with a reason). `components/layout/menu/plan-indicator.tsx` shows the tier and the upgrade path.
- **Sign-up**: one person is one account. `handle_new_user` creates the profile AND the personal workspace from `display_name`; the sign-up metadata also carries `locale` (the phase 2 trigger reads `display_name`, `segment`, `ai_tool`, `locale`). `/auth/complete-profile` is only the safety net for an account without a workspace.
- **Usage events**: the browser reports only offers shown and clicked (`trackOffer` in `lib/product-events.ts`, which terminates the PostgREST builder with `.then()`: a bare `void supabase.rpc(...)` never sends the request). Everything that counts toward a metric is written by the backend with `trackServerEvent` (`lib/product-events-server.ts`). The database stamps segment, language and AI tool from the profile and drops any property outside its allowlist.
- Reusable blocks live in `components/product/*` and are listed in `components/product/catalog.json` (injected by the `product-screen-guard` hook). Every zero-data view uses `EmptyState`.

## Public site (marketing layer)

- Routes in `src/app/(marketing)/`: home `/`, `/planos`, `/contato`, `/ajuda`, `/blog`, `/legal/{termos,privacidade,cookies}`. Phase 7.2 adds `/como-funciona`, `/catalogo`, `/sobre`, `/espera`, `/verificar/[ref]` and the founders page. Each new public route goes to `PUBLIC_PREFIXES` (`src/middleware.ts`), and an indexed one to `src/app/sitemap.ts`.
- ONE design system: pages compose the primitives in `src/components/marketing/` (`Section`/`Container`/`SectionHeader`, Hero, FeatureRows, BentoGrid, StatBand, PricingSection, Faq, Cta), listed in `components/marketing/catalog.json`. The inherited Landing DS is gone. `docs/DESIGN.md` holds the provisional direction; phase 7.3 rewrites it.
- `/ajuda` and `/blog` render DB-managed content (written in `/admin/help` and `/admin/blog`) through `src/lib/public-content.ts` (anon client, published rows, locale with EN fallback); Markdown renders via `components/marketing/markdown-prose.tsx` (raw HTML ignored).
- **The legal pages still render the inherited MedChina text** from the `marketing` namespace. Phase 2 seeds the flyee.club terms in `consent_terms` (pt-BR and en), and the pages must render that table before the first deploy.
- Pricing reads plans through `@flyee/billing/public` (`listPublicPlans`, read-only) with i18n placeholder plans as fallback; the contact form sends through `@flyee/email` (`CONTACT_FORM_TO`).
- Display type: `font-display text-display-{2xl,xl,lg,md}` (fluid clamp scale from `@flyee/design-tokens/css/marketing.css`). Motion: GSAP only inside marketing client components via `<Reveal>`/`useGSAP` (transforms + `autoAlpha`, honors `prefers-reduced-motion`); never in admin code.
- Tracking: the marketing layout renders Meta Pixel and GA4 server-side (opt-out through the cookie notice, `lib/analytics.ts`); sign-up and purchase conversions go server-side (`lib/meta-capi.ts`, `lib/ga4-mp.ts`). `docs/TRACKING.md` is rewritten in phase 7.3.

## Billing and checkout

- `/settings/billing` (plan grid, current subscription, cancel and undo, invoices, billing profile, pending checkout, payment recovery) and `/assinatura` (the focused checkout, PIX or card). Server actions in `settings/billing/actions.ts`; provider webhooks at `api/webhooks/[provider]/route.ts`, idempotent through `claim_billing_webhook_event`/`complete_billing_webhook_event` with an attempt ceiling.
- **Dunning grace**: `past_due` keeps access for a configurable window (`platform_settings` key `dunning`) counted from `subscriptions.past_due_since`; `billing_past_due_grace_ends()` is the one answer every gate shares. Installed tools always keep working; only updates stop.
- **Comped plans**: `set_org_plan(org, plan, note)` puts a workspace on a tier without checkout (betas, partners, the team). It updates the live row instead of inserting, keeps the period bounds NULL, refuses a provider-backed subscription (`provider_managed`) and stamps `self_grant` in the audit event when the operator comps their own account.
- The founders offer counts real seats (`lib/founders-offer.ts`); the guarantee window comes from `platform_settings` (`lib/guarantee.ts`); a pending PIX survives a closed tab (`lib/pending-pix.ts`).
- Phase 4 adds the one-time access purchase (kit), entitlement grants, monthly and annual families, routing by currency (BRL → Asaas, USD → Stripe), price snapshots on subscriptions and cancellation reasons. See `docs/PLANO-IMPLEMENTACAO.md`, phase 4.

## Platform admin and account

- Superadmin area at `src/app/(dashboard)/admin`: `layout.tsx` is a server gate on `profiles.is_superadmin` (RLS stays the real defense); the Admin menu group renders only for superadmins (`hooks/use-is-superadmin.ts`). Consoles: `/admin` (metrics via `admin_metrics()`), `/admin/organizations` (accounts and people; ban, 2FA state and reset need `SUPABASE_SERVICE_ROLE_KEY`), `/admin/billing`, `/admin/ai` (model price book), `/admin/audit` (audit trail + sign-in log), `/admin/insights`, `/admin/backups`, `/admin/announcements`, `/admin/help`, `/admin/blog`, `/admin/support`. The accounts view and dossier still carry the inherited fields; phase 6 rewrites them as `admin_members_overview()`/`admin_member_dossier()`.
- Every mutation records an audit event through `lib/audit.ts` (`recordAudit`). Sign-ins are logged by a database trigger; members see their own in `/settings/security`.
- **Granting the superadmin role** (`set_user_superadmin(user, value, note)`): the flag is fenced by a trigger on `profiles` keyed on WHO is asking (`is_superadmin()` reads the database), because a self-`PATCH` of `is_superadmin` would otherwise promote any signed-in user. Self-change is refused in both directions. A session with no JWT (service role, migration, psql) passes: that is how the first superadmin is made.
- **Support impersonation** (`lib/impersonation-actions.ts`, started from `/admin/organizations`): the operator works inside a member's account through a **parallel session cookie** (`@flyee/auth` `authCookieName`), so leaving deletes a cookie and never strands the operator. Load-bearing: the write fence is in the DATABASE (`is_impersonated()` matches the JWT `session_id` against `impersonation_sessions`; triggers refuse member-owned writes), and it never expires; ending a visit uses `signOut({ scope: "local" })`, never the global default; starting requires the operator's own session at AAL2; credentials and `/admin` are blocked in the middleware. A reason is required, the member is notified, and the access is labelled as support in their sign-in history. Duration lives in `platform_settings` (`impersonation`).
- **Account deletion** (`delete-account-dialog.tsx`, server action `deleteAccount`, RPC `admin_delete_account(user, confirm_email, reason)`): the unit is the account plus every workspace it alone belongs to. The order is fixed: re-read the preview, cancel any live provider subscription (a failure deletes nothing), run the RPC in one transaction (it deletes rows that hold data through NO ACTION/RESTRICT references first, holder before held, and purges `record_versions`), then remove storage files through the Storage API using `admin_orphaned_account_storage`, which refuses anything still alive. Refused in the database: yourself, any superadmin, a support session, a live provider subscription. The audit event `admin.account.deleted` survives with counts only.
- **AI spend** (`lib/ai-spend.ts`, price book at `/admin/ai`): every provider call records one `ai_spend` row through the `ChatProvider` `onUsage` sink. Prices are configuration (`platform_settings` key `ai_prices`, per million tokens), shipped empty; an unpriced model reports `priced = false`, and consoles show the unpriced count beside every total. Cost is stored in USD micros and converted only with an operator-set rate.
- `/admin/insights` (`api/admin/insights/route.ts`): the model writes SQL from an `information_schema` catalog and each statement runs inside a `read only` transaction with a 5 s `statement_timeout`. **The read-only transaction is the safety boundary, not the prompt.** Every executed query is audited and shown. Needs `DATABASE_URL` and one AI provider key.
- **Daily operator watch** (`lib/admin-jobs.ts`, Inngest cron): one bell notification and one e-mail per superadmin, only when there is something to report; `notifications.source_key` makes the whole digest idempotent per day. Phase 6 replaces it with the weekly segment digest.
- `/admin/backups` (`@flyee/backup`): nightly cron plus "Run backup now" (inline fallback without Inngest). Archives land in the private `backups` bucket; downloads are signed URLs.
- Account plumbing is real: the header bell reads `notifications` (create rows server-side with `lib/notifications.ts`), announcements render in the dashboard layout with per-user dismissal, `/settings` edits the profile (avatar in the `avatars` bucket) and credentials. The quick-support widget (`components/support/support-widget.tsx`) reads the channels from `platform_settings` (`support`, edited at `/admin/support`), falls back to `BRAND.support`, and renders nothing until a human channel exists.

## Auth

- Supabase through `@flyee/auth` (`client`/`server`/`middleware`/`service`). `src/middleware.ts` refreshes the session and protects everything except `/` and `PUBLIC_PREFIXES`. Without `NEXT_PUBLIC_SUPABASE_URL`/`NEXT_PUBLIC_SUPABASE_ANON_KEY` the middleware no-ops and the auth screens show a configuration hint.
- 2FA (TOTP): enrolled at `/settings/security`; the middleware forces the AAL2 step-up at `/auth/two-factor`.
- Internal redirects go through `lib/safe-next.ts` (`sanitizeInternalNext`), never a raw `next` parameter.
- The OAuth 2.1 server (`/oauth/authorize`, `/api/oauth/register`, `/api/oauth/token`, `lib/oauth/*`, opaque tokens with a rotating 30-day refresh) becomes the CLI token server in phase 3: first-party `flyee-cli` client, loopback redirects with any port, device authorization for machines without a browser, revocation, and new scopes (`profile:read`, `catalog:read`, `modules:download`, `telemetry:write`).

## Commands (run from the monorepo root)

- `npm run dev` — dev server. `npm run build` — production build. `npm run typecheck` — TypeScript 5.8 pinned to this app.
- `npm run test:web` — vitest. `npm run test:e2e` / `npm run test:a11y` — Playwright against a production build (`e2e/baseline.spec.ts`).
- `npm run lint:fix` / `npm run prettier` — lint and formatting.

## Watch out

- `src/style/global.css` imports tokens from `@flyee/design-tokens/css/*`; never recreate tokens locally.
- Deploys go ONLY through GitHub Actions (`.github/workflows/deploy.yml`: `vercel pull/build/deploy --prebuilt`); the Vercel Git integration stays disconnected. Runbook: `docs/DEPLOY.md`.
- Server-only secrets (`DATABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, provider keys) never reach client components.
- `apps/web/.env` holds inherited MedChina production credentials and `apps/web/.env.local` blanks them; keep `.env.local` until the flyee.club services exist (root `CLAUDE.md`, "Safety during the transition").
