# flyee.club web (apps/web)

Next.js 15 (App Router) + React 19 — the only app of the flyee.club platform: public site, member dashboard, checkout, admin consoles and the CLI delivery API. See the root `CLAUDE.md`, `docs/PRODUCT.md` and `docs/PLANO-IMPLEMENTACAO.md`.

> The database is the baseline in `packages/db/migrations` (`0000`–`0018`, plus the migrations added since, described in `packages/db/README.md`). Prefer the function name when searching for a rule.

**`apps/web/ARCHITECTURE.md` is the map of how the app works, area by area, with its files, tables and migrations.** Read the section of the area before changing it (the language of a request, the member dashboard, the public site, billing and checkout, the admin consoles and the account, messages and jobs, auth and the CLI delivery API), and update that section in the same change when a mechanism is added or moved.

## Stack and conventions

- **UI**: MUI v9 is the base of the signed-in areas (member dashboard, admin, sign-in, checkout, onboarding, the CLI screens); the public site renders without it ("The public shell" below). Before building a component there, look for a MUI or MUI X equivalent (installed: Data Grid, Charts, Date Pickers, Tree View, Lab). MUI X is the free packages only: what only a Pro or Premium package has is built as our own component, and the platform holds no licence key (root `CLAUDE.md`, golden rules). Icons: **Phosphor** through the `@/icons/nexture/*` tsconfig alias (real adapters plus Nexture fallback stubs, see `src/icons/README.md`); never import an icon library directly. Import the one icon you render; `src/icons/icon-registry.tsx` (icons by NAME, for the dashboard menu and catalog icons) imports the whole set and ships all of it to any client component that imports it.
- **Styling**: MUI theme driven by CSS variables (`hsl(var(--token))`) from `@flyee/design-tokens`. Two stylesheets, both in CSS layers (`theme, base, mui, components, utilities`): `src/style/base.css` is loaded by every page (Tailwind, the tokens, `style/base/elements.css`, the site's motion and its primitives in `style/site/site.css`), and `src/style/app.css` carries the MUI component overrides (`src/style/**`), imported by `components/layout/app-shell.tsx` alone; it starts with `@reference "./base.css"`, so its `@apply` resolves utilities without emitting them a second time. Tailwind 4 for layout utilities, merged with `tailwind-merge`. The primary has two colours beside its three steps: `primary-contrast` (the label on a primary fill) and `primary-ink` (the primary as a foreground on the page); MUI's `contrastText` is the first, and `style/**` overrides with the second wherever MUI would paint text, an outline or a checked control with `palette.primary.main` (`lib/palette-contrast.test.ts`). Run `npm run check:mui-classes` after touching `src/style/**`.
- **Themes**: one locked palette (`theme-yellow`, the yellow of the logo) × light/dark, as classes on `<html>`. The tokens are scoped to those classes, so the root layout renders them on the server (the palette and the default mode) and a script in `<head>` corrects the mode before the first paint for a browser that stored another choice; in the signed-in areas `src/theme/theme-provider.tsx` keeps them in sync afterwards and applies only a palette listed in `THEME_OPTIONS` whatever a browser has stored (the public site has no provider: the script is the whole of its theming). Never leave the classes to a client effect again: until it ran, the page had no palette at all. Fonts: Mulish (`--font-body`), Londrina Solid (`--font-heading`; `font-display` falls back to it) and JetBrains Mono (`--font-mono`, every `<code>`/`<pre>` and `font-mono`). Londrina Solid ships Regular and Black only: MUI `h1`/`h2` and the display scale are Black, `h3`–`h6` and any heading under 24px are Regular (`font-normal`).
- **Forms**: Formik + Yup in the signed-in areas; a public form validates with plain state and the rules of its server action. Semantic data (phone, CPF/CNPJ, CEP, money) uses `components/product/fields/*`, never a raw `TextField`; persist digits, never masks.
- **i18n**: next-intl; every user-facing string goes through messages. Locales `pt-BR` (default) and `en`; catalogs in `packages/content/messages/`. `src/lib/i18n/messages.test.ts` pins key parity, no blank values and identical ICU placeholders. `node scripts/prune-messages.mjs --check` fails on keys no code renders and on keys the code renders that the catalog lacks. Namespaces: `marketing` (public site), `auth`, `product` (member dashboard, billing, settings), `dashboard` (chrome and menu). The home's copy lives in `components/marketing/home-copy/{pt-BR,en}.ts`; `pt-BR.ts` is the structural source of truth (`HomeCopy = typeof homeCopyPtBR`); the text follows `docs/HOME-COPY.md`, the home copy the product owner delivered.
- **Admin copy is hardcoded pt-BR**, outside i18n: the operator surface has one reader. Code comments stay in English; a database value (enum, slug, status) is mapped to a label, never shown raw. `components/data-grid/data-table.tsx` takes its grid chrome from MUI X's own locale pack.
- **Which language a request is in**: `i18n/request.ts` alone decides it. The public site takes the URL (pages under `app/[locale]/`, declared in `src/i18n/routing.ts`; internal links through `LocaleLink`/`localizeHref` with the Portuguese path). Every other area takes the visitor's cookie, else detection at render time, which never switches a crawler and always announces an automatic switch (`ARCHITECTURE.md`, "Which language a request is in").
- **Path alias**: `@/*` → `./src/*`. **Brand**: identity comes from `@flyee/content` (`src/brand.ts` re-exports it); the logo is the single component `src/components/logo/logo.tsx`, which references the official SVGs in `public/brand/` (light-surface and dark-surface files; `tone="contrast"` on the deep band) and never redraws them. The favicons, the square mark and the home-screen tile are generated from the mark: `npm run brand:assets`.
- **Remote data**: `lib/remote-state.ts` (`RemoteState<T>`: idle, loading, success, empty, error). An error is never rendered as empty.

## Rules of the code

Each rule is explained in the section of its area in `ARCHITECTURE.md`.

- **Screens**: a member screen's `page.tsx` reads with the member's session through `lib/member/*` (`getMemberContext()`), and a console's reads through `lib/admin/*` inside `loadConsole()`; both hand a `state` (`ready` | `error` | `unavailable`) to a client view with plain props, so an error is never rendered as empty. Every write goes to the database function that owns the rule: a member's through `lib/member/actions.ts`, a console's through a server action that calls `requireSuperadmin()` again and records an audit event. Reusable product blocks live in `components/product/*`, listed in its `catalog.json`; every zero-data view uses `EmptyState`.
- **Entitlements**: screens branch on `org_entitlements(org)` (`hooks/use-entitlements.ts`, `@flyee/billing/entitlements`), never on plan names or slugs; RLS and the RPCs still refuse what a screen does not offer.
- **FlyeeClub Pro on the click**: a Pro control is never disabled. Without the right it calls `useUpgradePrompt()(feature)` with one of `PRO_FEATURES`, and the server still refuses the action. A Pro area with nothing published says "Em breve".
- **The AI installs**: no screen gives a command as a task. Where something has to be installed, added or connected again, the screen mounts `AskAiBlock`; a new sentence is a key `ask-ai-*` with `{url}`, and the command it leans on has to be in `/instalar.md` (`lib/install-guide.test.ts`).
- **Usage events**: what counts toward a metric is written by the backend with `trackServerEvent`; the browser reports only offers shown and clicked (`trackOffer`). Activation steps are live predicates, never click tracking.
- **The public shell**: no MUI, styling engine, snackbar or form library on a public page (`lib/public-shell.test.ts`, the `[mui-on-public]` lint). Every signed-in segment wraps its children in `components/layout/app-shell.tsx`, a new top-level segment with pages included. A new public page is declared in `src/i18n/routing.ts` (both addresses), enters `src/app/sitemap.ts` when indexed and spreads `publicPageMetadata({ path, locale })` into its `generateMetadata`.
- **A public page arrives complete**: no loading boundary above it (no `app/loading.tsx`, no `<Suspense>` in the root layout), no loader overlay, and what it shows above the fold is decided before the first paint, from `<head>`. Do not add to its cost: no scripted animation, no client component where a server one does, no message a client component does not read, one icon import per icon. Every number on a public page comes from the database.
- **Motion and tracking**: CSS first; GSAP only through `<Parallax>`, on demand, never in admin code; transform and opacity, `prefers-reduced-motion` honoured, nothing runs forever. Site events are declared with `data-track`/`trackAttributes()` and sent by the one listener; never a third tracker, and none on `/admin`.
- **Prices**: every price goes through `formatPrice` (`@flyee/billing/currency`), with no struck-through price and no "from/to" pair (`lib/honest-pricing.test.ts`). Billing webhooks are idempotent (`claim_billing_webhook_event`), and billing notices never throw.
- **Messages**: every message to a member is written in the reader's language, from `lib/messages/bell-copy.ts` or `packages/email/src/copy/*`, never at a call site; a plan is called by `plans.name`. A job that writes to people claims, then sends: a message may be lost, never sent twice. Without `RESEND_API_KEY` nothing breaks. A job missing from `app/api/inngest/route.ts` never runs.
- **Security**: every `/api/cli/*` handler runs inside `runCliRequest` (`lib/cli/gates.ts`). `/admin/insights` runs each statement in a read-only transaction, which is the safety boundary, not the prompt. Support impersonation's write fence is in the database, and a visit ends with `signOut({ scope: "local" })`, never the global default.

## Commands (run from the monorepo root)

- `npm run dev` — dev server. `npm run build` — production build. `npm run typecheck` — TypeScript 5.8 pinned to this app.
- `npm run test:web` — vitest. `npm run test:e2e` / `npm run test:a11y` — Playwright against a production build (`e2e/baseline.spec.ts`).
- `npm run lint:fix` / `npm run prettier` — lint and formatting.

## Watch out

- `src/style/base.css` imports tokens from `@flyee/design-tokens/css/*`; never recreate tokens locally. A rule a public page needs goes in `base.css` (or a file it imports), never in `app.css`, which the public site does not load.
- Deploys go ONLY through GitHub Actions (`.github/workflows/deploy.yml`: `vercel pull/build/deploy --prebuilt`); the Vercel Git integration stays disconnected. Runbook: `docs/DEPLOY.md`.
- Server-only secrets (`DATABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, provider keys) never reach client components.
- `apps/web/.env` and `apps/web/.env.local` hold production credentials, of the hosted flyee.club project and possibly still of MedChina: never open, print or copy them (root `CLAUDE.md`, "Safety during the transition").
